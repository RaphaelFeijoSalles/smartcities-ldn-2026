# Escopo e Definition of Done

**NENHUMA FEATURE FOI APROVADA AINDA.** A lista abaixo define o método, não funcionalidades presumidas.

## P0 — o mínimo que leva à final
- [ ] Uma jornada completa do usuário definida e demonstrável.
- [ ] Entrada de dados válidos de exemplo, identificados como **sintéticos**.
- [ ] Uma transformação/decisão útil e justificável.
- [ ] Resultado observável com explicação de valor.
- [ ] Funciona num notebook local mesmo se internet/API falhar.
- [ ] Testado por outra pessoa; instruções de execução conhecidas.
- [ ] Demo, screenshots e vídeo de backup preparados.

## P1 — se P0 já funcionar
- Melhorar interface, estados de falha e acessibilidade.
- Adicionar uma integração autorizada e confiável, se imprescindível.
- Uma métrica visual adicional que melhore decisão.

## P2 — fora do hackathon salvo decisão explícita
- Login/roles completos, assinaturas, cobrança, integração com órgão real, cloud complexa, motor multiagente, painel administrativo genérico, infraestrutura sem necessidade de MVP.

## Critérios para dizer "PR pronta"
- Issue com aceite claro; diff no ownership; testes executados descritos; nenhuma credencial; sem regressão da demo; revisão de outro integrante.
